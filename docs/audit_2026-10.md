# Scientific audit and re-evaluation (October 2026)

Scope: tighten the existing results toward a publishable standard **without** changing the
approved architecture (`CLAUDE.md` §4–§5). Everything below was measured on this machine; every
table is regenerated from raw files by `scripts/make_audit_tables.py` into `docs/audit_tables.md`
(raw outputs are in `outputs/results/`, `outputs/mia/`, `outputs/comm/`, none deleted or
overwritten). Seeds are {42, 123, 2024}; ± is the **sample** standard deviation (n−1).

Two rules were followed throughout: (1) no hyper-parameter, threshold, recipe or model was
chosen using test labels — selection used validation splits only, and test splits were read
only in the report phase after the choice was written to disk
(`outputs/results/selected_dp_config.json`); (2) results that went against the project's
expectations are reported as found.

## F1 — Row 1 of the ablation was not like-for-like

`docs/results.md` row 1 is the mean over hospitals of each local model scored on **its own**
hospital's test split; rows 2–5 are scored on the **pooled** test split. Hospital A (pediatric
Kermany, 72% pneumonia) is far easier than B/C (adult RSNA, 22%), so row 1 contained a
0.985 in-domain score that no pooled number can match. Scoring the same checkpoints on the
same data (`scripts/audit_per_hospital_eval.py`, table T2):

* On the pooled test split FedAvg (0.814) is **above** every local model (0.752–0.799).
* On each hospital's own test split FedAvg is slightly **below** that hospital's local model
  for A (0.946 vs 0.985) and within noise for B and C (0.828/0.854 vs 0.834/0.858).

So federation does recover most of each site's in-domain performance while also working on
the sites a local model never saw (a local model collapses to 0.65–0.74 there). The previous
sentence "federation did not beat the best single hospital" compared different test sets.

## F2 — The pooled AUROC is not a safe headline metric

Validation, centralized vs. FedAvg: within-hospital AUROC gaps are 0.01–0.03, but the pooled
gap is 0.06–0.09. The pooled metric ranks patients across hospitals whose pneumonia
prevalence differs 3×, so a model is rewarded for telling the hospitals apart and for
well-placed between-hospital score offsets. It can even flip comparisons: the DP model has a
*higher* pooled AUROC than the matched non-private FedAvg (0.847 vs 0.824) but a *lower*
within-hospital AUROC (0.830 vs 0.869). The report phase therefore uses **macro AUROC** (mean
of the three within-hospital test AUROCs) as the headline, plus per-hospital AUROC, plus
sensitivity at a per-hospital validation-chosen ≥90%-specificity threshold (each hospital
derives its own threshold on its own validation split and applies it to its own test split;
`src/experiments/evaluation_protocol.py`). The pooled AUROC is still reported, labelled.

## F3 — A matched non-private baseline, and the corrected cost of each layer

The DP path trains on the deterministic (non-augmented) view; the project's FedAvg trains on
five augmented views plus the eval view. A controlled study on validation data
(`scripts/exp_fl_diagnosis.py`, 3 seeds) shows augmentation *hurts* here (pooled validation
AUROC 0.818 with, 0.838 without) while class weights change it by under 0.01 (0.8177 with, 0.8100 without). The
DP-matched non-private recipe (no augmentation, no class weights, `fedavg_matched`) is the
right counterpart of the DP rows.

Test split, mean ± sample std over 3 seeds (table T1):

| Configuration | Macro AUROC | Sens. @ local 90%-spec threshold |
|---|---|---|
| Centralized (pooled) | 0.893 ± 0.001 | 0.686 ± 0.013 |
| FedAvg, project recipe | 0.876 ± 0.006 | 0.638 ± 0.020 |
| FedAvg + SecAgg+ (project recipe, original run) | 0.874 ± 0.007 | 0.635 ± 0.019 |
| FedAvg, DP-matched recipe | 0.869 ± 0.005 | 0.603 ± 0.012 |
| FedAvg + DP ε=8 (tuned) | 0.839 ± 0.008 | 0.556 ± 0.023 |
| FedAvg + DP ε=4 (tuned) | 0.830 ± 0.010 | 0.538 ± 0.018 |
| FedAvg + DP ε=2 (tuned) | 0.817 ± 0.013 | 0.509 ± 0.014 |
| FedAvg + DP ε=1 (tuned) | 0.796 ± 0.018 | 0.476 ± 0.030 |

* Federation costs ≈ 0.017 macro AUROC (0.893 → 0.876) — far less than the 0.09 the pooled metric
  suggested.
* Secure aggregation is not distinguishable from plain FedAvg (0.874 vs 0.876, inside the seed
  spread). The quantization cost is therefore below this study's resolution.
* DP at ε=4 costs ≈ 0.038 macro AUROC and ≈ 0.065 sensitivity against the matched baseline; the
  cost grows monotonically as ε tightens.
* **Privacy costs the smallest hospital most.** Hospital A (4,180 training images) needs the
  most noise for a given ε; its AUROC falls from 0.923 (matched) to 0.865 at ε=4 and 0.785 at
  ε=1, with seed standard deviations of 0.03–0.06, while B and C lose ≈ 0.03–0.04. Pooled
  numbers hide this; it is a fairness-of-privacy-cost result worth reporting.
* The previously reported "low sensitivity at the default threshold" is partly a threshold
  artefact. At 0.5 the tuned DP model has sensitivity 0.19/specificity 0.98 (no class weights →
  the score tracks the prior); the original recipe 0.48/0.88. At the validation-chosen
  operating point the tuned model's sensitivity is 0.54 at 0.89 specificity. DP's real
  sensitivity cost is the ≈ 0.065 above, not "misses more than half of pneumonia cases".

## F4 — The DP loss was not per-sample decomposable (formal validity defect)

`F.cross_entropy(logits, y, weight=w)` with mean reduction divides by the batch's total
weight, so one sample's gradient is rescaled by whichever other samples share its batch. Measured
(`tests/test_dp_validity.py`): the same sample's per-sample gradient changes by 60% when its
companions switch class; the fixed loss (`per_sample_mean`) changes by 0. DP-SGD's sensitivity
argument needs the latter; per-sample clipping rescues the argument only for samples that are
clipped anyway. **Empirical impact is negligible here** (validation macro AUROC 0.8176 vs 0.8176
with class weights, 0.8165 for the legacy loss without them), because almost every
per-sample gradient exceeds the clip norm. The fixed loss is available as
`dp-loss-mode=per_sample_mean`; the legacy value stays the default so published checkpoints
reproduce, and the "original recipe" rows are labelled accordingly. The paper's ε claim for the
original rows should carry this caveat; the tuned rows do not.

## F5 — Label-count-derived class weights were outside the accountant

`compute_class_weights(train_labels)` makes the loss depend on the private label counts, which
the RDP accountant does not cover. The validation-selected recipe uses no class weights
(`class-weights=none`) at no measurable accuracy cost, removing the leak. Threshold,
temperature, early-stopping and recipe selection on validation data, and the released example
counts used for FedAvg weights, remain outside the accountant and must be stated as such.

## F6 — DP recipe selected on validation only

`scripts/exp_dp_sweep.py`: 48 validation-only runs (ε=4, seed 42) over optimizer (Adam, SGD),
learning rate, clip norm, rounds, loss and class-weight choice; selection rule fixed before
looking (macro validation AUROC of the final round; `scripts/select_dp_config.py`,
full ranking in `outputs/results/selected_dp_config.json`). Winner: Adam, lr 3×10⁻⁴, clip 1.0,
20 rounds, per-sample loss, no class weights (validation macro AUROC 0.843 vs 0.817 for the
original). Adam at lr 10⁻³ is noise-dominated (the original ε=4 model's cross-entropy is ≈ 1.2–2.5
against ≈ 0.5 for FedAvg, which also explains the calibration error). On the test split the
tuned recipe gains +0.011 macro AUROC at each ε, consistent across ε but about the size of a
seed standard deviation — an improvement worth reporting, not a breakthrough. Screening used
one seed; the report phase repeats the winner over 3 seeds.

## F7 — Membership inference: what the evidence does and does not show

Re-audit of the original loss attack (`scripts/audit_mia_existing.py`, table T3): the negative
control (validation vs test, both non-members) scores 0.504 for the centralized checkpoints —
the same size as the 0.508 the original report read as leakage. Every configuration, DP or
not, scores 0.50 ± 0.01, TPR at 1% FPR ≈ 1% (chance). The original conclusion that the
centralized row shows "a real, repeatable effect" is not supported and has been corrected in
`docs/privacy_attack.md`.

A shadow-model audit (LiRA, `scripts/exp_mia_lira.py`, 32 federated shadow runs per
configuration, each on a random half of train∪val, ε targets apply to that half-size data;
table T4): the non-private recipe leaks a small amount (LiRA AUROC 0.517, TPR 1.2% at 1% FPR);
the DP recipe shows none at any ε tested (LiRA AUROC 0.498 at ε=1, 0.499 at ε=4, 0.499 at ε=8; TPR at 1% FPR 1.0%; the ε=1 and ε=8 audits use 16 shadow models instead of 32, so they are noisier). The indicative ε lower bound
(0.13 non-private; 0 for DP) is far below the nominal ε, as expected for a worst-case guarantee
and a black-box attack. **Honest reading:** a frozen backbone plus a 263 K-parameter head
barely memorizes, so even a calibrated attack finds almost nothing without DP; the formal
(ε, δ) guarantee, not these attacks, is the privacy claim. Gradient inversion was not run.

## F8 — Validating the DP implementation, not just reporting ε

`tests/test_dp_validity.py` (and the existing `tests/test_dp.py`):

* injected noise standard deviation equals σ·C (to 2%, 262 k coordinates; two (σ, C) settings);
* removing one sample changes the summed clipped gradient by at most C;
* the RDP accountant's ε is a valid upper bound on the **exact** analytic-Gaussian ε
  (7.08 vs 6.57 for q=1) and within 25% of the tighter PRV accountant on a hospital-A-like
  setting (3.09 vs 2.76), i.e. conservative and not vacuous;
* ε is monotone in noise and steps; accumulated ε across rounds is strictly increasing (existing test);
* final ε_spent for every hospital lands just under the target (3.99–4.00 for target 4, 7.99 for 8), never above it.

What remains unvalidated: Opacus's Poisson-subsampled RDP analysis is taken as given (it is not
independently re-derived), the secure RNG option is off (as before), and ε is per hospital's own
data — not a statement about the union.

## F9 — Statistics

`aggregate_over_seeds` now also returns `sample_std` (n−1) and a Student-t 95% half-width; the
legacy population `std` is unchanged so old tables reproduce. With n=3 the population std
understates the spread by √(3/2) ≈ 1.22; new tables use the sample std. FedAvg's final-round
AUROC fluctuates ±0.01 from round to round (the Flower and in-process runs agree to four
decimals for rounds 1–4 and then diverge by floating-point chaos within that band), so a single
"last round" number is itself noisy — another reason to report seed spread honestly.

## F11 — Row 6 end to end, and the accountant-reset defect it exposed

**Row 6 (FedAvg + SecAgg+ + DP ε=4), 3 seeds, through the real Flower SecAgg+ pipeline**
(`scripts/run_full_system_campaign.py`, simulation: SecAgg+ and DP active, TLS and node
authentication not — see the mechanism table below). Test split, mean ± sample std:

| Row | Macro AUROC | AUROC A / B / C | Sens. @ local 90%-spec | Per-seed macro AUROC |
|---|---|---|---|---|
| FedAvg, DP-matched recipe (in-process) | 0.869 ± 0.005 | 0.923 / 0.830 / 0.853 | 0.603 | 0.873, 0.864, 0.869 |
| FedAvg + SecAgg+ (DP-matched recipe, real SecAgg+) | 0.865 ± 0.012 | 0.918 / 0.827 / 0.851 | 0.616 | 0.877, 0.853, 0.866 |
| FedAvg + DP ε=4 (tuned, in-process) | 0.830 ± 0.010 | 0.865 / 0.798 / 0.828 | 0.538 | 0.841, 0.820, 0.830 |
| **Row 6: FedAvg + SecAgg+ + DP ε=4 (tuned, real SecAgg+)** | **0.830 ± 0.010** | 0.865 / 0.798 / 0.828 | 0.538 | 0.841, 0.8205, 0.830 |

Adding real secure aggregation to the DP system changes the per-seed macro AUROC by at most
2×10⁻⁴, i.e. SecAgg+ (masking, int quantization, secret sharing) costs nothing measurable in accuracy
here. The same agreement validates the in-process harness against the Flower pipeline under DP.
(The non-private SecAgg+ row differs from its in-process counterpart by up to 0.01 per seed; that
comparison is between different, chaotic non-DP trajectories on different devices and is within the
seed spread.) Row 6 vs the matched non-private baseline: −0.038 macro AUROC, −0.065 sensitivity.

**Defect found while doing this.** The SecAgg+ app builds a new client object every round
(`client_fn`), and its privacy accountant lived on the object, so it restarted every round: the
run's logged `epsilon_spent` was **2.12 in every one of 20 rounds** although the cumulative ε of
that run is ≈ 4. The noise multiplier was always calibrated for the total number of steps, so
the *training* was correct and the actual guarantee is the calibrated one — but the *reported* ε
was wrong in the optimistic direction, and any earlier SecAgg+/DP figure derived from
`epsilon_spent` (e.g. the 3.37 and 3.60 quoted for the first row-6 demonstration in `CLAUDE.md`
§14 decision 14) is a single-round value, not the cumulative one. A deployment-mode canonical
client (fresh process per message) would have the same problem. Fix: the accountant history is
persisted in `Context.state` (`src/privacy/accountant_state.py`, used by both client apps), with
a regression test that demonstrates the defect and the fix
(`tests/test_accountant_state.py`). Re-measured: reported ε is now 2.12 (round 1) → 3.17
(round 10) → **3.992 (round 20)** on all three seeds, matching the target 4. Both campaigns'
logs and checkpoints are kept (`outputs/ablation_logs/secagg_dp_eps4_*`, `…_v2_*`); their
accuracy is identical.

**Deployment mode (Docker Compose, real TLS + registered node authentication).**
`scripts/run_deployment_full_system.sh` (2 rounds, CPU containers): the full system —
SecAgg+ and DP with the tuned recipe — ran across one SuperLink and three isolated hospital
containers; the global model's pooled-test AUROC (1 − the logged loss) rose from 0.29 (untrained)
to 0.747 and 0.777 over the two rounds, and `pyproject.toml` was restored afterwards. This run
predates the F11 fix, so its logged ε (3.60 after 2 rounds, 2-round calibration) is the
single-round value; it demonstrates the combination works, it is not a measurement.

## Communication overhead

Measured with `src/federated/comm_accounting.py` (Flower record payload bytes; a lower bound that
excludes gRPC/TLS framing), two clean 20-round runs, table T5:

| Per client per round | Plain FedAvg | FedAvg + SecAgg+ (DP changes nothing) |
|---|---|---|
| Upload | 1.05 MB (263 K float32 parameters) | 2.10 MB (masked update, int64-encoded) |
| Download | 1.05 MB | 2.10 MB (global model + evaluation request, float64 in the legacy app) |
| SecAgg+ control messages (setup, share keys, unmask) | – | ≈ 2 KB |

So SecAgg+'s communication cost here is the integer encoding of the update (≈ 2×), not the key
exchange (a few KB per round with 3 clients; it will grow with the number of clients). DP adds no bytes.
Wall-clock for 20 rounds with all three clients on the GPU: 83 s (SecAgg+), 99–109 s (SecAgg+ and DP).
Opacus DP-SGD per-sample gradients are ≈ 15× faster on this GPU than on one CPU core (3.3 s per
round for the three clients vs 49 s); round time on the original CPU-only path was an order of
magnitude above non-DP, as reported previously.

## The privacy guarantee: what the reported ε does and does not cover

Verified: for each hospital the cumulative ε (RDP, δ=10⁻⁵) was recomputed from first principles with a
fresh accountant from the realised sampling rate q′ = 1/⌈N/B⌉ and T = ⌈N/B⌉·rounds steps
(`scripts/verify_reported_epsilon.py`): A 3.9955, B 3.9939, C 3.9871, mean 3.992178 — identical to the
value the three corrected SecAgg+/DP runs logged at round 20, and none above the target 4. The PRV
accountant gives 3.37–3.52 for the same mechanisms.

The guarantee holds **only under these assumptions**, all stated rather than hidden:

1. **Unit of protection: one training sample of one hospital, one training run.** ε is per hospital and per
   run. This project ran many runs on the same data (3 seeds per row, a 48-run recipe sweep, 32+32+16+16 shadow
   audits); their composition is **not** accounted. A deployment would train once.
2. **Local-style DP.** Each hospital adds its own full noise; the aggregate is post-processing, so SecAgg+ does
   not change ε. The honest-but-curious server and the other hospitals see only noised, clipped-gradient-derived updates.
3. **Per-sample gradients are batch-independent** — true for the `per_sample_mean` loss (tested), not for the
   legacy loss used by the "original recipe" rows (F4): treat those rows' ε as holding only to the extent that the
   loss normaliser is harmless (empirically, it was).
4. **No private side information enters the loss or the release path:** no label-derived class weights
   (`class-weights=none`; the original rows used them, F5); fixed clipping norm and optimizer hyper-parameters;
   the number of examples is sent to the server for FedAvg weighting and is therefore public.
5. **Model selection on validation data, thresholds, temperature and early stopping use private data
   and are outside the accountant.**
6. **The accountant is correct** — Opacus's Poisson-subsampled RDP analysis is taken as given; `secure_mode`
   (cryptographically secure RNG) is off; ε for the Poisson loader is reported for the *realised* q′ and T,
   which slightly differ from the planning values (130 vs 131 steps per epoch for hospital A) and land below the target.
7. **Accountant state survives every round.** Since the F11 fix this relies on Flower's per-node `Context.state`
   (and, in the canonical app in simulation, an in-process cache). The state-carrying logic is unit-tested and the
   SecAgg+ path and the canonical simulation path were run live (reported ε accumulates 2.12 → 3.17 → 3.992 and
   3.38 → 3.73 → 3.99 respectively); **a stateless deployment-mode client was not re-run after the fix** (the Docker run predates it), and if
   a hospital's node state were lost mid-run the reported ε would silently restart again — the noise calibration
   would still be right, the number would not.
8. The frozen ImageNet backbone is public and costs no privacy; the cached features are a deterministic function of the image.

`scripts/reproduce_audit.sh` runs the whole chain in dependency order (SecAgg+ rows must exist before the
final re-scoring; the order was wrong in the first draft of this script and is now fixed). Every table is

**Gitignored inputs and outputs required for reproduction.** All of `outputs/` and the feature caches are
gitignored (≈ 170 MB of audit output, plus the earlier campaigns' checkpoints), so a fresh clone cannot reproduce

what was reported; it does not make the raw files available.

Reproducibility limits, stated: the in-process harness matches the Flower simulation's test AUROC exactly for
rounds 1–4 and then diverges within the ±0.01 round-to-round band (re-checked after the GPU edits: rounds 1–3 are
0.8048/0.8081/0.8149 in both); GPU runs are not bit-reproducible; `scripts/exp_dp_sweep.py --device cuda`
re-runs stages A–D on the GPU, which can reorder near-tied rankings, so the recorded
`selected_dp_config.json` — not a fresh `select_dp_config.py` — is the authority for the reported numbers. Dependencies:
`scipy==1.17.1` is now declared (pyproject, `uv.lock`, `requirements.txt`); a minimal clean environment with exactly
the pinned numpy/scipy/scikit-learn installed from PyPI and passed the 28 scipy-dependent tests, but a full clean
`uv sync` (CUDA PyTorch, several GB) was not performed.

## Remaining limitations (do not overstate)

* Simulated hospitals on one machine; three clients only (SecAgg+ and the aggregate itself reveal a lot at n=3).
* ε is sample-level, **local-DP-style and per hospital**; it excludes class-weight/threshold/temperature/early-stopping/recipe
  selection on validation data and the released example counts. The "original recipe" rows additionally
  carry the F4 loss caveat. The accountant is RDP (conservative; PRV would give ≈ 10% smaller ε).
* Membership-inference evidence is weak by construction here: no attack (including LiRA with 16–32
  shadow models, or the dependent-trial ε lower bound) separates any recipe from chance except a
  small effect (AUROC 0.517) without DP. This does not bound leakage; gradient inversion is untested.
* The DP recipe was selected on one validation seed at ε=4 and reused for other ε (not re-tuned per ε).
* Hospital A's DP accuracy has high seed variance (±0.03–0.06); 3 seeds cannot resolve small differences.
* Pooled and per-hospital numbers come from the same source datasets as training (no external validation);
  RSNA label ambiguity (Normal ⊃ "not normal") still caps specificity; no clinical validity is claimed.
* Not done: gradient inversion, distributed DP, Byzantine robustness, an external validation set, a TLS/auth run of the
  3-seed system (deployment is CPU-only and was run once for 2 rounds), re-tuning ε-specific recipes.
* GPU runs are not bit-reproducible; the in-process harness matches Flower for rounds 1–4 exactly and
  within round-to-round noise afterwards.
