# Reproducibility

`CLAUDE.md` §12: "a result that is not in MLflow does not exist" and reproducibility
ranks above raw accuracy in this project's priority order (`CLAUDE.md` §2). This
document is the map from a reported number back to the exact config, seed, and
MLflow run that produced it.

## How a number in `docs/results.md` traces back

**Rows 1–2 (Local, Centralized)** — `outputs/results/local_baseline.json` and
`outputs/results/centralized_baseline.json`, produced by `scripts/train_local.py`
and `scripts/train_centralized.py` respectively. Each file stores, per regime
(`natural` / `balanced`) and per metric, the full `values` list across 3 seeds plus
the `mean`/`std`/`n_seeds` already aggregated — nothing in `docs/results.md`'s rows
1–2 is computed outside these two files.

**Rows 3–5, Dirichlet rows (FedAvg, SecAgg, DP)** — every real federated run is
tracked as one MLflow run in experiment `federated_ablation`
(`sqlite:////mnt/storage/pneumonia-detection/mlruns.db`), logged by
`src/federated/server_app.py` (FedAvg / DP path) or
`src/federated/server_app_secagg.py` (SecAgg path). `src/evaluation/tables.py`
queries MLflow directly — by `params.partition_path` + `params.dp_enabled` for
FedAvg/DP rows, by run-name prefix for SecAgg — and aggregates
`final_pooled_test_auroc` across whichever runs match. **No number in these rows is
hand-copied**; running `uv run python -m src.evaluation.tables` reproduces the table
from the live database every time.

## What is frozen for this table's scope (owner-approved, Stage 21)

- **Seeds:** `{42, 123, 2024}` — every row in `docs/results.md` is exactly these
  three seeds, no more, no fewer. `src/evaluation/tables.py` treats any additional
  matching MLflow run as a genuine data point rather than silently ignoring it,
  which is precisely how the Stage 23 MLflow-contamination bug (below) was caught.
- **Rounds:** 20 server rounds, uniformly across every configuration in the table.
- **Dirichlet sweep:** alpha in `{0.1, 1.0}`, 3 clients — a supplementary,
  non-primary comparison, not folded into the natural/balanced regimes.
- **Row 6 (full combined system)** was explicitly deferred by owner decision during
  Stage 21 scoping, in favor of measuring SecAgg's and DP's costs independently
  (rows 4 and 5). Not implemented, not silently approximated.

## Partitions

`data/partitions/hospitals_natural.json`, `hospitals_natural_balanced.json`,
`hospitals_dirichlet_alpha0.1.json`, `hospitals_dirichlet_alpha1.0.json` are
committed (not gitignored — `.gitignore` explicitly allowlists
`data/partitions/*.json`) precisely so a third party can reproduce the exact same
train/val/test patient assignment without re-running the partitioning seed
themselves. `hospitals_dirichlet_*` were generated by
`scripts/build_partitions.py::build_dirichlet_ablation_partitions()` at
`DIRICHLET_ABLATION_SEED = 2100`.

## Config

Every run is fully specified by Hydra config plus `flwr run`'s
`--run-config` overrides — no hand-edited constants between runs
(`CLAUDE.md` §12). `pyproject.toml`'s `[tool.flwr.app.config]` holds the
committed defaults (e.g. `mlflow-tracking-uri`, `mlflow-experiment-name`); the
ablation sweep (`scripts/run_ablation.py`) overrides `partition-path`, `seed`,
`dp-enabled`, and `target-epsilon` per run via `--run-config`.

## Two Flower API surfaces — a real, load-bearing detail

This project runs two different `server_app.py` variants against the same
`ClientApp`:

- **`src/federated/server_app.py`** — Flower's newer Message-API
  (`@app.main()`, `ArrayRecord`, `Grid`), used for the FedAvg and DP rows. This is
  the path Stage 20's overhead instrumentation (`payload_bytes`,
  `wall_clock_seconds`) is wired into.
- **`src/federated/server_app_secagg.py`** — Flower's legacy `Strategy` /
  `ClientManager` / `workflow` API, required specifically because SecAgg+'s
  built-in workflow (as of the pinned Flower 1.35.0) is not yet available under
  the newer Message-API surface (Stage 15's own finding). This is why the SecAgg
  row in `docs/results.md` has real accuracy data but not yet the same
  payload/wall-clock instrumentation — it is a genuinely separate code path, not
  an oversight in the same file.

Both variants drive the identical `ClientApp` (`CLAUDE.md` ADR-8: one client
implementation, never forked between simulation and deployment, or — here —
between aggregation strategies).

## Environment

Exact pinned dependency versions live in `pyproject.toml` / `uv.lock` (never
duplicated into prose docs, including this one — see `CLAUDE.md` §4). Reproduce the
environment with `scripts/setup_env.sh` or `uv sync --all-groups`, then verify with
`uv run pytest tests/`.

## Seeding

`src/utils/seeding.py` seeds `torch`, `numpy`, `random`,
`torch.use_deterministic_algorithms(True)`, DataLoader worker seeds, and —
separately, since these are the two most commonly-forgotten seeds in FL work
(`CLAUDE.md` §12) — the data-partition seed and the client-sampling seed. The
partition seed is fixed once at partition-build time (`scripts/build_partitions.py`)
and the resulting indices are committed as JSON rather than re-derived per run, so
the *partition* itself is identical across every seed in the seed set above; only
model initialization, DP noise, and any stochastic training behavior vary by seed.

## A real reproducibility bug, found and fixed during this project

`tests/test_integration_smoke.py` (Stage 22, CLAUDE.md §11.3's required "2-client,
single-round smoke test") ran a real `flwr run` invocation for genuine end-to-end
coverage — but, before the Stage 23 fix, did not override
`mlflow-tracking-uri`, so it fell through to `pyproject.toml`'s real default and
silently wrote extra runs into the *actual* campaign database on every test
execution. This diluted the "3. FedAvg (natural)" row's seed aggregation (3 real
seeds became 6 mixed real+contaminating "seeds", pulling the mean down) the next
time the table was regenerated. It was caught by noticing an unexpected `n_seeds: 6`
while regenerating `docs/figures/` for this very document, traced to 3 stray MLflow
runs by timestamp and metric value, and fixed by redirecting the test's
`mlflow-tracking-uri` to an isolated `tmp_path` sqlite file
(`tests/test_integration_smoke.py`). This is recorded here deliberately: it is the
kind of silent-corruption failure mode `CLAUDE.md` §12's reproducibility priority
exists to catch, and it was caught by the same "a result that is not in MLflow does
not exist" discipline that makes it visible when a row's `n_seeds` doesn't match
what was intended.
